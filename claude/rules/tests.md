# Tests

A test added with a change holds the fewest assertions that tell the new behavior from the old, at least one of them failing on the old code. A variant that tells no new case apart goes, and so does a test per member the change touches the same way.

## Names

A test name is the line a reader consults instead of the body, so it states a behavior as a whole clause: an actor, an active verb, and the observable result. Third person, verb-first where the unit under test is the actor – `encodes zero as canonical decimal`, `allows_requests_when_no_token_is_configured`. Where no grouping level names the unit – a flat file, or a PHPUnit class covering several – the identifier opens the name instead: `frontend_url_returns_null_when_not_configured`. It opens only the cases that belong to one unit; a case that holds for the whole class – a retry policy, an auth check every method shares – stays verb-first, since a prefix would single out a unit the test does not. The subject slot otherwise belongs to a particular input, precondition, or collaborator that acts – `changing_the_password_revokes_an_existing_grant`, `cleanup cancels an in-flight standalone preload`.

For a transformation the object is the input and the complement the result: `encodes zero as canonical decimal`, not `emits canonical decimal for zero`. Verbs like `returns` and `throws` name the result outright and take no input in the object. The main clause never goes passive, which would drop the actor the name exists to fix, so `a_draft_is_never_locked` becomes `never_locks_a_draft` – a trailing condition may stay passive where its agent is beside the point, as in `allows_requests_when_no_token_is_configured`. An invariant that has no actor keeps its copula and states the law: `every_source_code_is_also_a_target_code`.

Name the actual value the test picks and the actual identifier, never a paraphrase of either – `1e-7`, `--delimiter`, `--stats`, `options.path`, `ctx.request`, and the exported name the code itself uses, so a test for `cleanup` says `cleanup cancels an in-flight standalone preload` and never `disposer`. The precision rule for identifiers in `code-style` applies unchanged: `rejects a non-numeric --indent`, not `rejects invalid indent value`, and a preposition usually replaces a `when X is …` clause outright – `prints the stack trace with --verbose`. A parenthesis may carry why a value is the interesting one: `encodes 1e-7 (just below lower boundary) as exponent form`. A constant the code tunes – a budget, a deadline, a cap, a lifetime – goes by its role, and so does a value derived from it: `cuts a description to its maximum length`, not `cuts a description to 300 characters`. A value published in a tool description, a README, or a documented default keeps its number. Backticks stay out of a name, except where the literal is also an ordinary English word and the backticks are the only thing marking it as code – falls back to `text` for unmapped field types. A parameterized case has no value to name at authoring time, so it names the invariant and lets the interpolation supply the row; the invariant still owes a real verb – `converts %p to %s` rather than `handles %p as %s`, and `resolves_target_language` where the runner appends the data set itself.

`describe` names the unit or the behavior area, as a bare noun or verb – `encode`, `options`, `error reporting`, `word length`. It explains nothing and names no mechanism: `word length at the default ratio` says in the group what belongs in the case, and grouping by `stdin edge cases` or `streaming output` sorts tests by how they are wired rather than by what they promise. A parenthetical is for separating two groups that would otherwise read alike – `createPngDataUri (BlurHash)` beside `createPngDataUri (ThumbHash)`, and likewise where the separator is the environment – never to explain a group. A PHPUnit class is the coarser equivalent, a noun ending in `Test` that often covers several units, which is why what it cannot say moves into the method's opening word. Two levels of nesting is the limit, past which no single line reads on its own.

The name says nothing the suite's setup has already fixed – not the transport, not the fixture, not the environment. Where every case in a group is fed the same way, `encodes JSON from stdin with custom delimiter` is `encodes with a custom --delimiter`. It never restates the group's noun for its own sake, though it may inflect the group's verb and keep a word the clause is false without, since the case has to stand as a clause on its own line: under `describe('encode')`, `it('encodes an empty object')` is right and `it('encode encodes an empty object')` is not. What it never borrows is the fixture's own subject matter, which describes a sample API rather than the unit – `handles requests without options for inventory lookup` is `invokes fetch without options`.

Some verbs assert only that something happened, and each one hides the behavior the name owes the reader. `handles`, `supports`, `works with`, `can …`, `properly …`, and `correctly …` are rewritten to the verb that says what: `returns ofetch result for pet lookup requests` becomes `returns the fetch result unchanged`. The ban reaches their nominalizations in a group name too, where `prompt handling` and `mixed file handling` are `handles` in a noun's clothing. A name never opens with `should`, `test that`, or `verifies that` – every test asserts, so the words carry nothing and cost the sentence its verb slot. These rules hold against any example to the contrary in a skill or a borrowed suite, for names you write.

A rename needs a clause above that the old name breaks; two compliant names make a lateral move, and it stays unmade. In a suite someone else owns, a name that breaks no clause keeps the neighbouring specs' style.

One sentence, no terminal period, lowercase from the first word unless that word is an identifier the code capitalizes (`BigInt normalization`, `TypeValidationError`). A test name is a label, not prose, and the punctuation rules for comments do not reach it. PHP writes the same sentence with underscores for spaces and no `test` prefix, the method carrying `#[Test]` instead: `translateMany` plus `batches texts in a single request` is `translate_many_batches_texts_in_a_single_request`. The framework's own surface – `it` against `test`, `it.each` against a loop, file naming, snapshot policy – is a per-project choice and nothing this rule speaks to.
